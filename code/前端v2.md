# 📘 AI 交互式小说共创平台 - 产品需求规格说明书 V3.0

> **核心理念**: **"Chat with your Story" (与故事对话)**。
> **转变**: 从“工具箱模式”转变为“流式共创模式”。用户不再是孤独的打字员，而是掌舵的“导演”；AI 是提供无限可能性的“演员”和“编剧顾问”。

## 1. 产品形态与交互逻辑 (Product Identity)

废弃传统的“左侧目录+右侧文档”的 Word 式布局。采用类似 **ChatGPT + Notion** 的混合形态：

* **中央舞台 (The Stream)**: 故事以“卡片流”或“聊天气泡流”的形式呈现，而非单一的长文本。每一次交互（一段剧情）都是一个“节点”。
* **右侧仪表盘 (The HUD)**: 实时悬浮的“驾驶舱”，展示雷达图、关键情报、伏笔回收情况。
* **底部控制台 (The Director's Bar)**: 输入指令、选择种子、控制走向的核心区域。

---

## 2. 详细功能模块 (Functional Modules)

### 🚀 模块 A: 流式共创编辑器 (Co-Creation Stream)

这是核心写作区，融合了 **想法2** 的“功能+独创”理念和 **方案1** 的“多分支选择”。

* **1. 节点式写作 (Node-based Writing)**:
* 文章不再是纯文本，而是由一个个 `Turn` (回合) 组成的序列（对应后端 `stories.json` 结构）。
* 每个 `Turn` 可以被点击、修饰、重写。


* **2. 意图与种子系统 (Intent & Seeds) [核心创新]**:
* 当用户需要 AI 续写时，不直接生成，而是先弹出一个**“灵感罗盘”**：
* **输入意图 (Functionality)**: 用户输入简单的指令，如 *“制造冲突”*、*“描写心理”*、*“推进到高潮”*。
* **选择种子 (Originality)**: 系统随机漂浮出几个“概念词”（如：*镜子、深渊、红酒、量子*）。用户点击一个，AI 将尝试把这个概念融入剧情，带来意外的惊喜（参考**方案2**）。




* **3. 平行宇宙卡片 (Plot Cards) [参考方案1]**:
* AI 响应指令时，不生成唯一的文本，而是生成 **3 张剧情卡片 (Plot Cards)**。
* 每张卡片包含：
* **摘要/梗概**: 一句话描述这段剧情发生了什么。
* **预览**: 前 50 字的预览。
* **标签**: 如 *#反转*、*#温情*、*#悬疑*。


* **交互**: 用户点击某张卡片 -> 该卡片内容展开并正式写入故事流（力场收束）。



### 📊 模块 B: 全知仪表盘 (Omniscient Dashboard)

位于右侧，利用 `media-backend` 的数据和 DeepSeek 的分析能力，提供上帝视角。

* **1. 人设/剧情雷达图 (Radar Metrics)**:
* 利用 AI 分析当前上下文，实时绘制五维雷达图：
* **冲突 (Conflict)**
* **情感 (Emotion)**
* **节奏 (Pacing)**
* **信息量 (Info Density)**
* **逻辑性 (Logic)**


* *技术实现*: 前端调用后端 `/analyze` 或新接口，由 LLM 打分返回 JSON。


* **2. 核心情节点提取 (Key Plot Points)**:
* 自动提取当前故事的“记忆锚点”。
* 例如：*“第3章：侦探发现了带血的硬币”*。
* 点击锚点可以快速跳转到对应段落。


* **3. 潜意识投影 (Semantic Flow) [保留 V2]**:
* 保留原有的 PCA 散点图，但将其缩小为一个小组件。
* 展示当前故事的“情绪轨迹”是从平庸走向高潮，还是在原地打转。



### 🧠 模块 C: 深度推理引擎 (DeepSeek Director) [NEW]

这是一个按需调用的高级功能，利用 `DeepSeek-Reasoning` 模型。

* **逻辑自洽性检查**: 用户点击“复盘”，AI 扫描全文，指出逻辑漏洞（如：*“主角在第2章腿断了，为什么第5章在跑步？”*）。
* **伏笔建议**: AI 建议：“你之前提到的‘金鱼’可以作为凶器，是否在接下来的剧情中回收这个伏笔？”

## 3. 前端重构方案 (Frontend Refactoring Plan)

基于 Vue 3 + Pinia + Tailwind CSS 进行开发。

### 3.1 目录结构 (Directory Structure)

```text
src/
├── components/
│   ├── StoryStream/
│   │   ├── TurnCard.vue       // 单个故事段落卡片
│   │   ├── ChoiceSelector.vue // 剧情分支选择器（3张卡片）
│   │   └── TypingIndicator.vue
│   ├── HUD/
│   │   ├── RadarChart.vue     // 雷达图 (使用 ECharts 或 Chart.js)
│   │   ├── PlotTimeline.vue   // 关键情节点列表
│   │   └── MiniMap.vue        // PCA 轨迹缩略图
│   └── InputBar/
│       ├── ConceptSeeds.vue   // 漂浮的概念种子
│       └── IntentInput.vue    // 意图输入框
├── stores/
│   ├── story.ts      // 管理 turns, currentStoryId
│   ├── suggestion.ts // 管理当前的 AI 建议、卡片、种子
│   └── analysis.ts   // 管理雷达图数据、PCA 数据
├── services/
│   ├── llm.ts        // 封装 generate, analyze 接口
│   └── ws.ts         // WebSocket 管理
└── views/
    └── Workbench.vue // 核心工作台页面

```

### 3.2 关键交互流程 (User Flow)

1. **初始化**:
* 加载 `Workbench`，WebSocket 连接后端。
* 加载历史 Turns，渲染为流式列表。


2. **触发续写**:
* 用户点击输入栏的 `✨ AI 续写` 按钮。
* **API 请求 1**: 获取“概念种子” (前端本地随机或后端生成)。
* 用户输入“意图”（如“揭露真相”）并选中种子“怀表”。


3. **生成选项**:
* **API 请求 2**: 发送 Context + Intent + Seed 给后端。
* 后端调用 DeepSeek/LLM 生成 3 个简短的 Plot Summaries。
* 前端展示 `ChoiceSelector` 组件。


4. **收束/确认**:
* 用户点击“选项 B”。
* **API 请求 3**: 请求生成该选项的完整正文。
* 正文流式打字机效果显示在 `TurnCard` 中。
* 后端保存，更新 PCA 坐标和雷达数据。

## 4. 后端适配需求 (Backend Requirements)

现有的 `media-backend` 代码结构非常好，只需少量扩展：

1. **新增接口 `/story/suggest**`:
* 输入：`story_id`, `intent`, `seed_word`。
* 输出：`options: [{ title, summary, mood }, ...]` (返回3个选项)。
* *Prompt 策略*: "作为策划，请根据上文和关键词[Seed]，提供3个截然不同的后续情节简述。"


2. **扩展接口 `/story/analyze_deep**`:
* 调用 DeepSeek-Reasoning 模型。
* 输出：雷达图数值 (5维)、关键情节点列表。


3. **Schema 扩展**:
* 在 `Turn` 中增加 `metadata` 字段，用于存储该段落对应的“意图”、“种子词”以及“雷达评分”，以便后续复盘。

## 5. 开发实施路线图 (Roadmap)

### 第一阶段：流式框架搭建 (The Stream)

* [前端] 搭建 `Workbench.vue` 布局（左中右结构）。
* [前端] 实现 `TurnCard` 组件，能够美观地渲染 `stories.json` 里的 Markdown/HTML。
* [后端] 确保 `/story/{id}` 接口能正确返回数据。

### 第二阶段：交互式续写引擎 (The Interaction)

* [前端] 实现底部 `InputBar`，包含“意图输入”和“种子气泡”UI。
* [后端] 实现 `/story/suggest` 接口 (Mock 数据先行，随后接入 LLM)。
* [前端] 实现 `ChoiceSelector` (三卡片选择 UI)。

### 第三阶段：全知仪表盘 (The Insight)

* [前端] 集成 `ECharts` 或 `Chart.js` 实现雷达图。
* [后端] 编写 Prompt 提取 plot points 和雷达维度分数。
* [前端] 将后端的 `x/y` 坐标渲染为微型轨迹图。

### 给开发者的建议 (Dev Tips)

1. **关于 CSS**: 推荐使用 **Tailwind CSS**，能极快地构建出“悬浮卡片”、“毛玻璃效果”和“流光按钮”，非常符合本产品的科幻/未来感。
2. **关于 WebSocket**: 现有的 `ws.py` 已经支持推送。建议在用户选择 Plot Card 后，使用 WS 流式传输生成的长文本，增强“实时感”。
3. **Prompt Engineering**: 这是核心。你需要精心调试 DeepSeek 的 Prompt，让它生成的“海龟汤”或“剧情卡片”足够有创意，而不是陈词滥调。

这份 V3.0 方案将原本静态的编辑器变成了**动态的叙事实验室**，完美契合你想要的高级辅助和聊天式交互体验。你可以直接把这个需求发给你的前端代码助手开始执行了！
