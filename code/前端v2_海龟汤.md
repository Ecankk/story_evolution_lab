# 🛸 增补模块设计：海龟汤力场收束游戏 (The Convergence Game)

> **核心隐喻**: **“收束 (Convergence)”**。
> **概念**: 每一个可能的真相最初都是混沌宇宙中的一颗星辰。用户的每一次提问和AI的回答，都是在施加“引力”，将无数可能的故事线（熵）收束为唯一的、合乎逻辑的真相（流）。

## 1. 页面定位与路由

* **页面名称**: `TurtleSoupGame.vue`
* **路由**: `/soup/galaxy`
* **定位**: 独立的沉浸式游戏页面，隐藏常规 UI，专注于视觉化的逻辑推理。

## 2. 核心交互流程 (Based on Plan 1)

这个页面将经历四个阶段，对应方案1中的“力场收束”过程：

### 🌌 第一阶段：宇宙大爆炸 (The Setup)

* **输入约束**:
* 用户（作为主持人/出题者）输入 **“汤面 (开头/表象)”** 和 **“汤底 (结尾/真相)”**。
* *或者*，用户只输入关键词，由 AI 生成这对约束。


* **初始化可视化**:
* 屏幕中心爆发出一片 **“粒子云”**（代表无数种可能的逻辑解释）。
* 起点（汤面）和终点（汤底）作为两个固定的 **“恒星”** 锚定在屏幕两端。



### 🔭 第二阶段：星辰观测 (Exploration)

* **AI 生成 (后端 /story/suggest)**:
* AI 基于开头和结尾，生成 3-5 个 **“中间推论节点”**（即方案1中的“星球”）。
* 这些节点散落在屏幕空间中（利用后端的 `x, y` PCA 坐标定位）。


* **可视化呈现**:
* **星球 (Planet)**: 每个节点是一个发光的球体。
* **大小**: 代表 **可信度 (Confidence)**。
* **位置**: 代表 **语义距离**（离真相越近，位置越靠拢终点）。



### ✋ 第三阶段：施加原力 (Apply Force)

* **核心交互 - 力场拖拽**:
* 用户不需要打分，而是直接 **拖动星球**。
* **靠近**: 如果用户觉得某个推论（例如“凶手是金鱼”）很有趣/很接近真相，将其向“主航道”拖动 → **增加权重**。
* **推远**: 如果用户觉得某个推论逻辑不通，将其推向边缘 → **减少权重**。


* **视觉反馈**:
* 随着拖动，背景中的 **“银河 (Vector Field)”** 流向会实时改变，模拟“水流”被引力改变的效果。



### 🧩 第四阶段：坍缩 (Collapse)

* **生成链条**:
* 当用户确定了几个关键节点的位置后，点击 **“观测坍缩”**。
* AI 将连接起点、用户选中的高权重节点、终点，生成一条连贯的 **“故事线”**。
* 这就完成了一局“海龟汤”的创作或解谜过程。

## 3. 前端技术实现方案 (Technical Plan)

为了实现方案1中描述的“星球”、“银河”和“力场”，常规的 HTML/CSS 已经不够，我们需要引入轻量级的可视化库。

### 3.1 推荐技术栈

* **D3.js**: 最适合做力导向图 (Force-directed Graph)，处理节点之间的斥力和引力算法非常成熟。
* **PixiJS** 或 **Three.js**: 如果追求极致的炫酷（粒子特效、发光光晕），建议使用 PixiJS（高性能 2D WebGL），开发成本比 3D 低，效果比 DOM 好。

### 3.2 关键组件设计 (`/components/SoupGalaxy/`)

1. **`UniverseCanvas.vue`**:
* 核心画布。负责渲染背景的“向量场”（流动的线条）和“节点”（星球）。
* 监听鼠标/触摸事件，处理拖拽逻辑。


2. **`NodePlanet.vue`**:
* 显示节点的摘要文字。
* 根据后端的 `entropy_score` 决定星球颜色的冷暖（熵高=红色不稳定，熵低=蓝色稳定）。


3. **`ForceController.ts`**:
* 前端逻辑类。模拟物理引擎：
* `Constraint`: 起点和终点是固定桩。
* `Attractor`: 用户的鼠标拖拽行为产生引力中心。



### 3.3 对接后端数据 (Integration)

我们需要复用并稍微“滥用”一下现有的 `Turn` 结构：

* **`Turn.x / Turn.y`**: 直接映射为画布上的坐标。
* **`Turn.flow_score`**: 映射为星球的 **质量/引力**（影响周围流场的强弱）。
* **`Turn.text`**: 星球点击后展开的内容。

**API 调用示例**:

1. 用户拖拽星球 A 到新位置 。
2. 前端调用 `/story/update_coords` (需新增或复用 update) 更新该 Turn 的坐标。
3. 后端重新计算 PCA 或仅仅更新权重，返回新的 `flow_score`。
4. 前端重绘流场。
